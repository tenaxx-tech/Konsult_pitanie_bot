# Подключение Airtable

## Что готово

Адаптер `nutrition.airtable` читает существующие Config, DailyState и Meals. Таблицы и поля обнаруживаются по именам; ID базы задаётся в среде, а не в публичном коде. Airtable — источник актуального дня; SQLite-дневник автоматически туда не выгружается.

Чтение существующей базы проверено через подключённый Airtable в ChatGPT. Прямой запуск Python против API требует отдельного PAT; авторизация коннектора ChatGPT не передаётся программе. Живая запись еды из программы пока не проверена. Проверки записи выполнены на тестовом клиенте.

## Настройка среды

1. Откройте https://airtable.com/create/tokens и создайте токен для своей базы питания.
2. Добавьте права `data.records:read`, `data.records:write`, `schema.bases:read` и доступ только к нужной базе.
3. В среде запуска добавьте секрет `AIRTABLE_TOKEN`. Не отправляйте токен в чат, не добавляйте его в файлы GitHub или команды с открытым значением.
4. Добавьте переменную `AIRTABLE_BASE_ID` с ID своей базы (начинается с `app`).
5. Разрешите исходящие HTTPS-запросы к `api.airtable.com` для самостоятельного запуска.

```bash
python -m nutrition.airtable --day 2026-10-02 read
```

Команда возвращает актуальные протоколы, строки и заново рассчитанные итоги. Если день CLOSED, авторитетным окончательным итогом остаётся сохранённый DailyState согласно ClosingProtocol. Программа не закрывает день и не начисляет баллы.

## Явная запись одной позиции

В приватном локальном JSON-файле подготовьте:

```json
{
  "MealItemKey": "2026-10-02|BREAKFAST|001",
  "Meal": "BREAKFAST",
  "Status": "PLANNED",
  "Source": "LABEL",
  "portion": {
    "name": "Название с этикетки",
    "grams": "180",
    "per100": {"kcal": "80", "protein": "18", "fat": "0.5", "carbs": "3"},
    "source": "Условный пример: замените данными этикетки",
    "basis": "ready",
    "estimated": false
  }
}
```

Не запускайте пример для реального дневника: значения условные. Для реальной записи используйте подтверждённые продукты и фактический DayKey. Ключ позиции должен быть постоянным и уникальным. Если запись уже существует, используйте её MealItemKey, а не создавайте новый ключ того же продукта.

После чтения текущей Version:

```bash
python -m nutrition.airtable --day 2026-10-02 upsert private-item.json --expected-version 3
```

Команда обновляет только указанную позицию, перечитывает все строки даты, пересчитывает Eaten/Forecast, увеличивает Version и проверяет запись чтением. Для подтверждения у той же позиции измените Status на CONFIRMED после явного сообщения пользователя «съел»/«выпил», используйте свежую Version. Изменение уже подтверждённой позиции разрешено только с `--correction`, после явной просьбы исправить факт. Закрытый день адаптер не изменяет.

Повтор того же события не создаёт дубликат. При ошибке записи сначала выполняется чтение для проверки, затем одна повторная попытка. Если позиция сохранилась, а агрегаты нет, повтор события восстанавливает агрегаты. Баллы, существующие цели и текст PlanSummary не перезаписываются.

Airtable не предоставляет общей транзакции для Meals и DailyState. Проверка версии уменьшает риск конфликта, но не заменяет атомарную блокировку. Используйте одного писателя: не запускайте одновременные изменения через несколько ассистентов. После сообщения о конфликте или частичной записи перечитайте день перед продолжением.

Замена позиции использует её прежний ключ. Удаление лишних позиций при замене целого блюда другим составом пока выполняется отдельно через коннектор и действующий протокол; адаптер не удаляет записи автоматически.

## Использование ассистентом

Подключённый коннектор Airtable позволяет ассистенту читать и писать записи независимо от Python. Для использования именно этого калькулятора ассистент должен иметь инструмент выполнения Python либо API-сервис, предоставляющий функции адаптера. Файлы GitHub сами по себе таким инструментом не являются.

При наличии выполнения Python: прочитать Config и текущий день; применить только явные пользовательские события; вызвать расчёт; записать через коннектор или адаптер; проверить чтением. Полный актуальный NutritionSyncProtocol и NutritionCalculationProtocol имеют приоритет. Для закрытия дополнительно применяется ClosingProtocol.

Обычный GPT без выполнения Python/API может пользоваться существующим коннектором, но не запускает этот репозиторий автоматически. Настройки уже созданного GPT необходимо обновлять в его редакторе; этот проект не изменяет их через GitHub.
