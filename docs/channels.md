# Telegram и ВКонтакте

Шлюз \`python -m nutrition.channels\` поддерживает личные сообщения Telegram-боту и сообществу VK. Оба канала используют один дневник Airtable и один калькулятор.

## Что работает

- \`/start\`, \`/help\`: список команд;
- \`/day\` или «сегодня»: текущий факт из Airtable;
- \`/calc JSON\`: расчёт массива portions;
- свободные текстовые вопросы владельца обрабатывает Gemini, если задан \`GEMINI_API_KEY\`; иначе используется Groq при наличии \`GROQ_API_KEY\`;
- проверка секретов входящих запросов и ID владельца;
- SQLite защищает от повторной обработки доставленных событий.

ИИ не записывает еду в Airtable. Запрос к ИИ содержит текст вопроса, до 12 предыдущих сообщений текущего дня и сводку сегодняшнего состояния/приёмов из Airtable. Доступ разрешён только владельцу; сообщения остальных пользователей не передаются модели.

## Настройки ИИ

- \`GEMINI_API_KEY\` — ключ Google AI Studio; хранить только в секретах Bothost. Если заданы оба ключа, используется Gemini;
- \`GEMINI_MODEL\` — модель Gemini; по умолчанию \`gemini-3.1-flash-lite\`;
- \`GROQ_API_KEY\` — запасной ключ Groq, если Gemini не настроен;
- \`GROQ_MODEL\` — модель Groq; по умолчанию \`openai/gpt-oss-120b\`;
- \`AI_DAILY_LIMIT\` — максимум 40 запросов за скользящие 24 часа; по умолчанию 40;
- между запросами действует пауза 10 секунд.

Собственный лимит бота ограничивает расход запросов. Gemini также применяет квоты и ограничения бесплатного тарифа; при HTTP 429 бот сообщит о временном ограничении, команды \`/day\` и \`/calc\` продолжат работать.

## Данные и приватность

Перед включением учитывайте: бот передаёт Gemini текст вопроса, историю до 12 предыдущих сообщений за текущий день и дневную сводку питания. На бесплатном тарифе Google указывает, что запросы могут использоваться для улучшения продуктов. Проверьте актуальные [условия обработки данных и тарифы Gemini API](https://ai.google.dev/gemini-api/docs/pricing) и не отправляйте через бота сведения, которые не хотите передавать этому провайдеру.

Проверить ключ одним минимальным запросом без дневника можно командой \`python -m nutrition.gemini_chat\`. Она отправляет только фразу «Reply with OK only». Эта проверка выполняет один реальный запрос к Gemini.

## Остальные настройки

Общие: \`AIRTABLE_TOKEN\`, \`AIRTABLE_BASE_ID\`, \`NUTRITION_TIMEZONE\`.

Telegram: \`TELEGRAM_BOT_TOKEN\` от BotFather, \`TELEGRAM_WEBHOOK_SECRET\` (случайная строка), \`TELEGRAM_OWNER_ID\` (числовой ID владельца).

VK: \`VK_ACCESS_TOKEN\` (ключ сообщества с доступом к сообщениям), \`VK_CALLBACK_SECRET\`, \`VK_GROUP_ID\`, \`VK_OWNER_ID\` и \`VK_CONFIRMATION_CODE\` из настроек Callback API сообщества.

Значения хранятся в настройках постоянного сервера, не в GitHub.

## Размещение

Нужен постоянный сервер с HTTPS-доменом и обратным прокси к Python. Codex-окружение служит для разработки и проверки, не заменяет постоянный сервер ботов.

Telegram webhook: \`https://YOUR_DOMAIN/telegram/webhook\`, при регистрации setWebhook передать secret_token с тем же значением TELEGRAM_WEBHOOK_SECRET.

VK Callback API: \`https://YOUR_DOMAIN/vk/webhook\`, включить события message_new и настроить тот же секрет, группу и код подтверждения.

Запуск: \`python -m nutrition.channels\`, по умолчанию слушает 127.0.0.1:8081. Настраиваются API_HOST, PORT, CHANNEL_DB. Храните файл CHANNEL_DB в постоянном томе; не запускайте несколько экземпляров шлюза с независимыми файлами.
