# Telegram и ВКонтакте

Подготовлен шлюз `python -m nutrition.channels` для личных сообщений Telegram-боту и сообществу VK. Оба канала используют один дневник Airtable и один калькулятор.

## Что работает в коде

- `/start`, `/help`: список команд;
- `/day` или «сегодня»: текущий факт из Airtable;
- `/calc JSON`: расчёт массива portions по формату калькулятора;
- проверка секретов входящих запросов и ID владельца;
- сохранение обработанных событий в SQLite для защиты от повторных уведомлений.

Это первоначальное подключение каналов. Свободный диалог, распознавание фотографий, предложения меню и запись еды по обычным фразам пока не реализованы. Внешние сообщения не отправлялись при тестировании: проверены входящие запросы и ответы через тестовый отправитель. Реальные Telegram/VK-токены и постоянный сервер ещё не настроены.

## Необходимые настройки

Общие: AIRTABLE_TOKEN, AIRTABLE_BASE_ID, NUTRITION_TIMEZONE.

Telegram: TELEGRAM_BOT_TOKEN от BotFather, TELEGRAM_WEBHOOK_SECRET (случайная строка), TELEGRAM_OWNER_ID (числовой ID владельца).

VK: VK_ACCESS_TOKEN (ключ сообщества с доступом к сообщениям), VK_CALLBACK_SECRET, VK_GROUP_ID, VK_OWNER_ID и VK_CONFIRMATION_CODE из настроек Callback API сообщества.

Значения хранятся в настройках постоянного сервера, не в GitHub. Разрешены только личные сообщения от заданного владельца. Данные других пользователей не включаются в этот персональный дневник.

## Размещение

Нужен постоянный сервер с HTTPS-доменом и обратным прокси к Python. Codex-окружение служит для разработки и проверки, не заменяет постоянный сервер ботов.

Telegram webhook: `https://YOUR_DOMAIN/telegram/webhook`, при регистрации setWebhook передать secret_token с тем же значением TELEGRAM_WEBHOOK_SECRET.

VK Callback API: `https://YOUR_DOMAIN/vk/webhook`, включить события message_new и настроить тот же секрет, группу и код подтверждения.

Запуск: `python -m nutrition.channels`, по умолчанию слушает 127.0.0.1:8081. Настраиваются API_HOST, PORT, CHANNEL_DB. Храните файл CHANNEL_DB в постоянном томе; не запускайте несколько экземпляров шлюза с независимыми файлами.

Текущий синхронный обработчик подходит для первичной проверки с одним владельцем. Перед постоянным использованием нужно добавить очередь фоновых задач, мониторинг и обработку таймаутов. Защита событий уменьшает дубли; при сбое между отправкой ответа и сохранением ID Telegram может получить повторный ответ.

Для свободного диалога следующий шаг — подключить модель через API, хранение истории и явные инструменты расчёта/записи. Одной подписки на чат с нейросетью недостаточно, если сервис не даёт программный API и размещение ботов.
