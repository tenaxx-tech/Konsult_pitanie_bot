# Telegram и ВКонтакте

Шлюз `python -m nutrition.channels` поддерживает личные сообщения Telegram и сообщения сообщества VK. Оба канала используют один дневник Airtable и калькулятор. Допускается только ID владельца; остальные пользователи игнорируются.

## Возможности

- `/start`, `/help`: справка;
- `/day` или «сегодня»: чтение факта текущего дня;
- `/calc JSON`: точный расчёт порций без изменения дневника; без JSON бот покажет формат и пример;
- свободные вопросы через GigaChat (основной провайдер), Gemini или Groq — выбирается первый настроенный ключ в этом порядке;
- сообщения о съеденной/выпитой еде преобразуются в структурированные позиции и записываются в Airtable как `CONFIRMED` только при явном сообщении о факте;
- планы сохраняются как `PLANNED` и не входят в факт;
- фото Telegram передаётся GigaChat Vision, распознанное предложение хранится как ожидание в SQLite и попадает в Airtable только после «Съел»/«Выпил». «Отмена» удаляет ожидание;
- состояние дня повторно читается, версии проверяются адаптером Airtable; события защищены от повторной доставки.

Если масса или блюдо не определяются, бот задаёт вопрос и не пишет позицию. Если пищевые значения основаны на модели, в Airtable ставится признак приблизительности. Пользователь может исправить позицию отдельным сообщением; закрытый день адаптер блокирует.

## Секреты и параметры

Общие: `AIRTABLE_TOKEN`, `AIRTABLE_BASE_ID`, `NUTRITION_TIMEZONE` (для Екатеринбурга `Asia/Yekaterinburg`).

Telegram: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_OWNER_ID`, `TELEGRAM_WEBHOOK_URL` (например, HTTPS адрес BotHost с путём `/telegram/webhook`). Регистрация URL выполняется `python -m nutrition.telegram_setup --register`; безопасная проверка без изменения URL — `python -m nutrition.telegram_setup`.

VK: `VK_ACCESS_TOKEN`, `VK_CALLBACK_SECRET`, `VK_GROUP_ID`, `VK_OWNER_ID`, `VK_CONFIRMATION_CODE`. В Callback API VK укажите `https://<домен>/vk/webhook` и включите событие `message_new`.

ИИ-провайдеры, по приоритету:

- `GIGACHAT_AUTHORIZATION_KEY`; `GIGACHAT_MODEL` по умолчанию `GigaChat-2`;
- `GEMINI_API_KEY` и необязательный `GEMINI_MODEL`;
- `GROQ_API_KEY` и необязательный `GROQ_MODEL`.

Для фото используется `GIGACHAT_VISION_MODEL` (по умолчанию `GigaChat-2-Pro`). Распознавание фото отправляет его содержимое в GigaChat API и может расходовать отдельные токены модели; обычный текст использует GigaChat-2. Временная копия загруженного фото удаляется после обработки, если API удаления доступен.

## Хранение и запуск

Контейнер должен иметь постоянный каталог `/app/data`; `CHANNEL_DB=/app/data/channels.sqlite3` хранит историю диалога, защиту от повторов и ожидающие подтверждения фото. Не запускайте несколько копий с отдельными БД.

Откройте исходящий HTTPS к `api.airtable.com`, `ngw.devices.sberbank.ru:9443`, `api.giga.chat`, `api.telegram.org`, `api.telegram.org/file` и нужному API альтернативного провайдера. Не выводите секреты в логи и не храните их в GitHub.
